# Tauri Complete DesktopApi Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every remaining Tauri `DesktopApi` placeholder with a real Rust-backed implementation while preserving the Electron backend and isolating Tauri preview data.

**Architecture:** A single Rust `AppState` owns the HTTP client and all session authorization state. Focused command modules implement settings, Tier List, Steam Collections, image export, Owned Games, and achievements; `src/platform/tauri-api.ts` remains a thin adapter that preserves the existing `DesktopApi` contract.

**Tech Stack:** Vue 3, TypeScript, Vite, Tauri 2, Rust 2021, Serde/serde_json, reqwest 0.13, Tokio 1, tauri-plugin-dialog 2, tauri-plugin-fs 2, tauri-plugin-opener 2

**Spec:** `docs/superpowers/specs/2026-09-30-tauri-complete-desktop-api-design.md`

## Global Constraints

- Keep the existing Electron preload, IPC channel names, backend modules, development scripts, packaging scripts, and release scripts unchanged.
- Keep the Tauri preview identifier `com.steampc.imagebrowser-tauri-preview` and its isolated `app_data_dir()` data.
- Do not import, share, overwrite, or migrate Electron settings, caches, collections, or Tier List data.
- Preserve every `DesktopApi` method signature and return shape; do not modify Vue component call sites.
- Keep Steam credentials and Steam HTTP request orchestration in Rust.
- Accept only fixed HTTPS Steam API endpoints; accept only valid HTTPS achievement icon URLs.
- Canonicalize every path before an authorization comparison, and compare path components rather than string prefixes.
- Do not grant WebView HTTP, shell, arbitrary opener, or wildcard filesystem permissions.
- Do not add a frontend opener or HTTP package; invoke opener only from Rust.
- Do not run tests, type checks, Rust checks, builds, `tauri dev`, or runtime verification. Tests are written for later execution but are not run in this implementation session.
- Do not commit Git changes. Preserve all pre-existing modified and untracked files, including unrelated release-script edits.

## Review Focus

- A source path containing `..`, or traversing a symlink/junction outside an authorized scan root, must be rejected before export; Task 4 adds canonical authorization tests.
- A forged `targetDirectory` that was never returned by the Rust directory picker must be rejected; Task 4 tests exact canonical target authorization.
- A Steam API transport error containing a query URL must not expose the API Key in the returned message; Tasks 5 and 6 test URL scrubbing.
- User-controlled app IDs, game names, and achievement IDs must not create path traversal or Windows reserved filenames; Task 6 tests component validation and sanitization.
- Corrupt cache files and partially invalid Tier List or Steam collection records must degrade to safe defaults without discarding unrelated valid records; Tasks 2, 3, 5, and 6 test these cases.

```rust
pub fn authorized_file(&self, file: &Path) -> Result<PathBuf, String> {
    let canonical = file
        .canonicalize()
        .map_err(|_| "图片文件不存在".to_string())?;
    if !canonical.is_file() {
        return Err("图片文件不存在".to_string());
    }
    if !self.is_authorized(&canonical) {
        return Err("未授权的图片路径".to_string());
    }
    Ok(canonical)
}
```

```rust
use std::{fs, path::{Path, PathBuf}};
use serde::Serialize;
use tauri::{AppHandle, Manager};

pub fn data_file(app: &AppHandle, file_name: &str) -> Result<PathBuf, String> {
    app.path()
        .app_data_dir()
        .map(|directory| directory.join(file_name))
        .map_err(|error| format!("无法确定应用数据目录：{error}"))
}

pub fn write_pretty_json<T: Serialize>(
    path: &Path,
    value: &T,
    label: &str,
) -> Result<(), String> {
    if let Some(parent) = path.parent() {
        fs::create_dir_all(parent)
            .map_err(|error| format!("无法创建{label}目录：{error}"))?;
    }
    let content = serde_json::to_string_pretty(value)
        .map_err(|error| format!("无法序列化{label}：{error}"))?;
    fs::write(path, content).map_err(|error| format!("无法保存{label}：{error}"))
}
```

Do not create a generic reader that treats all parse failures alike; each domain owns its validation and fallback.
